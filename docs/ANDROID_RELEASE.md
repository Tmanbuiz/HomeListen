# Permanent Android release signing

The ordinary **Build and check Home Listen** workflow creates explicitly labeled
preview APKs using a debug certificate. The new **Build signed Android release**
workflow requires your permanent signing key and builds a signed ARM64 APK plus
an Android App Bundle. It uploads artifacts only; it does not publish to an app
store or deploy the backend.

## Create or reuse your permanent key

If this application has already been distributed with a permanent signing key,
reuse that key. For a new release identity, generate a key on your own trusted
computer and keep its passwords and backup securely:

```sh
keytool -genkeypair -v -keystore homelisten-release.jks -keyalg RSA -keysize 3072 -validity 10000 -alias homelisten
```

The interactive command asks you for passwords. Do not put the key, passwords or
service credentials in the repository. `*.jks`, `*.keystore` and
`android/key.properties` are ignored by git.

For a local build, create `android/key.properties` with an absolute keystore path:

```properties
storeFile=/absolute/path/to/homelisten-release.jks
storePassword=YOUR_STORE_PASSWORD
keyAlias=homelisten
keyPassword=YOUR_KEY_PASSWORD
```

The same values can be supplied using `HOME_LISTEN_KEYSTORE_FILE`,
`HOME_LISTEN_STORE_PASSWORD`, `HOME_LISTEN_KEY_ALIAS` and
`HOME_LISTEN_KEY_PASSWORD`. Environment values take precedence. Set
`HOME_LISTEN_REQUIRE_RELEASE_SIGNING=true` when building for distribution so a
missing key fails instead of producing a debug-signed preview.

## GitHub Actions

In this repository's **Settings → Secrets and variables → Actions**, add:

| Repository secret | Value |
| --- | --- |
| `HOME_LISTEN_KEYSTORE_BASE64` | Your keystore encoded as base64 |
| `HOME_LISTEN_STORE_PASSWORD` | Keystore password |
| `HOME_LISTEN_KEY_ALIAS` | Permanent alias |
| `HOME_LISTEN_KEY_PASSWORD` | Alias password |

Run **Actions → Build signed Android release → Run workflow** on the reviewed
branch. The workflow checks code/tests before loading the key, writes it only to
the runner's temporary directory, requires release signing and removes the key
in its final cleanup step. Artifact paths include only the APK and app bundle.
Keep workflow changes under review before giving a branch access to signing
secrets.

An APK signed with a new certificate cannot update an existing debug-signed APK
in place. Switching certificates requires uninstall/reinstall, which clears
local data, pairing and settings. Back up any wanted history first. Subsequent
versions signed with the same permanent key can upgrade normally if their
Android version code increases. Store distribution may use a separate upload
key under Play App Signing; follow your existing store setup.

No permanent key is included or generated by this change. See Google's
[app signing documentation](https://developer.android.com/studio/publish/app-signing)
for key ownership, backups and store signing.
